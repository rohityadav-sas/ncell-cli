Authentication

Sign in with an OTP. The code is visible as you type:

ncell login 98XXXXXXXX

Resume instead of resending OTP again

ncell login 98XXXXXXXX --verify

Use this after an interruption or mistyped OTP. It resumes the pending login for that number without generating another OTP.

Inspect or remove the saved session

ncell status
ncell logout

  • status shows the logged-in number and session expiry.
  • logout deletes the local session and device ID.

Balance and profile

ncell balance
ncell profile
  • balance shows the current credit, data, voice and SMS balances.
  • profile shows the account number, name, SIM type, status, plan and payment mode.
  • --json returns the complete response object.

Search and sorting

ncell plans search "SMS" --category 50
ncell plans search "Super" --sort price
ncell plans search "Combo" --sort validity:desc,price:asc

Sort by more than one field

ncell plans search "SMS" --category 50 --sort validity:desc,price:asc
ncell plans --sort validity:desc --sort price:asc
ncell plans --sort validity,price

Supported fields are price and validity. Directions are asc and desc; default is asc.

Subscribe to a plan

ncell plans --category 50
ncell plans subscribe 984 --category 50

Use the category ID from the category list. --id is required; --category defaults to 66.

Send Free SMS

ncell sms send-free 98XXXXXXXX "Hello"

Sessions and token refresh

Tokens and device identity are stored under service ncell-cli, entry session, in your platform's native credential store.

Automatic refresh

  1. An authenticated request is rejected with HTTP 401 and LGN2001.
  2. The saved refresh token and matching device ID are used to refresh.

Manual refresh

ncell refresh

Command reference

Group related actions under their resource: plans categories, plans search, plans subscribe, sms send-free, and game check-in. Use plain words for actions and required inputs, and --long-name for options. Commands and options use lowercase kebab-case. Short flags such as -h are not supported. Quote inputs containing spaces. Use -- before a positional value beginning with a dash. Options such as --category 50 also accept --category=50.

--verify resumes a pending login; --category selects a catalog (default 66); --sort changes ordering (default price ascending). Sort keys accept commas or repeated --sort options, with optional :asc or :desc.

Game rewards

ncell game math automatically solves one math challenge, printing every answer and the final score/reward. Each game costs tokens. Supports arithmetic, parentheses, percentages, and averages. Unsupported questions prompt in the terminal: enter one of the displayed answer values, then automatic play resumes. The server time limit still applies. Prompts go to stderr, keeping JSON output separate. Request errors stop the game without retrying. A loss prints its score (and zero reward when none is returned), stops remaining games, and exits with code 1; wins exit with code 0. JSON preserves the server result. Use --count 3 --delay 1.5s to repeat games; delay applies between games. With --json, progress and final results are JSON records.

ncell game scratch --count 3 --delay 1.5s scratches cards using game tokens. It shares spin's count, delay, immediate output, and JSON options. Defaults to one card, and stops on the first failure without retrying.

ncell game spin spins once by default. Use --count 3 --delay 1.5s for multiple spins. Delay applies between spins: bare values mean seconds; s, m, and h accept decimals, such as 1.5h. Each spin spends game tokens and prints its result immediately. With --json, each successful response is a compact JSON object on its own line. Stops on the first failure; spins are never automatically retried.

ncell game ranks shows weekly performance, last week's result, the top players and prize tiers. This endpoint returns HTML; --json contains the extracted fields, with masked player numbers preserved.

ncell game status lists task IDs, progress, token and XP rewards, reset periods, and status. Use an ID from this list with game claim-task. Claimed tasks are green, completed tasks are yellow, and pending tasks use the default color. Colors are disabled for redirected output. Listing tasks does not claim rewards; --json includes the full response and summary.

ncell game status
ncell game status --json
ncell game ranks
ncell game ranks --json
ncell game spin --count 3 --delay 1.5s
ncell game scratch --count 3 --delay 1.5s
ncell game math --count 3 --delay 1.5s
ncell game check-in
ncell game claim-task 1,2,3
ncell game claim-task 1 2 3 --json

Task claims run sequentially using one web session. Each result prints immediately; JSON output is collected into one array. A server rejection is reported per task while remaining tasks continue; network or invalid-response errors stop the batch. JSON task output is an array containing each task ID and its server response. Already-completed tasks are normal results. The command exits unsuccessfully for other task failures.
